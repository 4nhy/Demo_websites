# ANGEL WIRE — Asset Manifest

Real files live under `public/images/<kind>/...` and are wired up via
`src/data/asset-manifest.ts` (id → file). This document is the source/license
record for every real asset on the site, per the asset strategy agreed before
implementation.

## Two asset classes, deliberately different sourcing rules

1. **Fictional ANGEL WIRE products** (the 20 catalogue pieces) — originally
   an **original, procedurally generated graphic representation**
   (fashion-industry "flat sketch" language: silhouette + material pattern +
   a hardware/detail close-up), generated by `scripts/generate-product-art.mjs`,
   no external source, no license concerns. **This rule has since been
   overridden for 7 of the 20 products, on explicit user instruction** — see
   "User-supplied product photography" below. The remaining 13 products are
   still procedural. **The hero pendant is no longer procedural at all** —
   see "Hero pendant" below; `scripts/generate-hero-heart.mjs` has been
   deleted, not just superseded.
2. **Editorial / collection / about imagery** — real sourced photography of
   objects, materials, and textures that establish the Y2K/thrift visual
   world, per the brief's explicit note: *"The image itself does not need to
   depict an ANGEL WIRE product."* Every file below is real photography from
   Wikimedia Commons, sourced directly (not scraped from Pinterest), checked
   individually for: (a) a license that permits reuse, (b) no identifiable
   real person in frame — two Commons candidates were downloaded and visually
   inspected during this pass and rejected for exactly that reason (a
   shopper photographed from behind at a clothing rack; a group photo with
   visible faces), consistent with the standing project rule.

pastel-holographic SVG → a from-scratch fleur-de-lis-cross SVG built to

## Reuse notes

A handful of ids intentionally reuse the same file across two pages that are
never visible side by side (e.g. a collection's hero photo also anchors its
homepage Lookbook look, since "the Angel Hour Edit" is naturally the same
visual world as the Angel Hour collection page). This was a deliberate
tradeoff under the available real-photo pool, not an oversight — every id
still resolves to a real photo rather than a placeholder.

## Still on `AssetPlaceholder`

None, as of this pass — every id referenced anywhere in the codebase has a
`REAL_IMAGES` entry. `AssetPlaceholder` remains in the codebase only as
`AssetImage`'s documented fallback path for any *future* id that doesn't yet
have a real asset.

## Found Objects — simplified to one photo, not three

Was a three-crop scattered layout wanting three distinct object photos;
only one was ever supplied, and the stopgap of repeating that one file
across all three slots (`collection-found-objects-object-0/1/2`, see the
now-superseded note this replaces below) was visibly a single photo
tripled, not a real three-crop moment. Per explicit instruction — no more
photos are coming for this collection — `CollectionChapter.tsx` and
`CollectionDetail.tsx` were simplified to a single hero image (After Dark's
layout, Found Objects' own mood/accent) instead. The `object-0/1/2` manifest
ids are removed, not just unused.

## Found Objects — replaced (visible logos)

The user-supplied Found Objects photo (a dark table of fur, bags, heels,
jewelry and sunglasses) failed the no-brand rule on closer inspection: a
**GUESS** logo on a bangle box, **Diesel** "D" logo plates on both heels, a
printed business card with a shop name, and a magazine cover with a face and
cover text. Replaced with a licensed stock photo at a **new filename**
(`found-objects-thrift.jpg` — reusing the old name let browsers and the
`/_next/image` cache keep serving the old photo), same 736×552 dimensions. Every id pointing at it (`collection-found-objects-hero`,
`COL-found-objects`, `L-found-objects` — collection detail hero, collections
index card, home Lookbook) was repointed in `asset-manifest.ts`.
